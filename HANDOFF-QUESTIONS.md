# HANDOFF-QUESTIONS (Tasks redesign, PC + shared model run)

Ambiguities found; each has a choice already made (closest to the prototype / safest for the hard rules). Update as the run goes.

| # | What | Where | Chose | Why |
|---|---|---|---|---|
| 1 | ADR number for "One task list with bins, labels and tags" | `doc/adr/` (here ends at 0072; the main checkout already has 0073-0075 uncommitted/other branches) | 0076 | Avoids a number clash when branches merge; ADR dir README to be updated |
| 2 | `02` §3.2 says labels keep category ids, but categories sync by name + colour only (no id on items or `SyncCategory`) | `Core/Sync/SyncCategory.cs`, `SyncNextTask.Category` | Label id = deterministic GUID from the lowercased name; old fields matched by name, case-insensitive | Both platforms can compute it with no talking; a rename is a stamped edit of each item (as ADR 72) |
| 3 | Numbering device: no primary/owner concept exists | `SyncDeviceCard`, `ReceivedDevicesService`, ADR 61 | PC with the lowest `DeviceId` among PCs seen; phone-only group numbers on the phone (temporary numbers on the PC meanwhile); mapping kept | Rule in `02` §4; deterministic. Known edge: a newly linked lower-id PC changes the numberer, so numbers are assigned once and never reassigned |
| 4 | Google Calendar export needs write access; today's scope is `calendar.readonly` | `Services/GoogleCalendarClient.cs` `Scope` | Do not build the export or the "AB Reminders" calendar; hide/disable the setting; Windows Calendar option also hidden | Stop condition 1 (broader scope / new consent); log, continue other work |
| 5 | Three overlapping histories: new History (30 d), session task history (90 d, ADR 72), Recently deleted (30 d) | `session.taskHistory`, `tasks.receivedHistory`, `RecentlyDeletedStore` | Keep the session records and Recently deleted untouched; the new History view reads finished (done bin/aged out) + archived + deleted tasks and links to them | Avoids breaking ADR 72 history sync and stats; no data moved |
| 6 | Auto-saved tasks and "Unfinished from <PC>" have no bin in the new model | `AutoSavedTaskStore`, `SessionTasksService.PastUnfinished` | Auto-saved → To sort with origin "Auto-saved <date>"; Unfinished-from-PC stays as the existing tidy-up/Notebook list | `02` §3 maps only next/Later/come-backs; nothing may be dropped |
| 7 | `PlannedFor` ("Put in plan", ADR 50) has no field in `02` §2 | `SessionTask.PlannedFor`, `PlannedSlot` | Keep it as an optional extra field on the task (not shown in the new UI); the day-part rule keeps working | Lossless migration; remove later with its own decision |
| 8 | ADR 72 `LocalTo` / handovers vs the new per-task `devices` list | `ISharedItem.LocalTo`, `TaskListSync`, `SyncHandover` | `LocalTo=k` ⇒ `devices=[k]`; keep the handover/receipt flow for moves between devices until the Android run | Same meaning; avoid rewriting working sealed-handover code now |
| 9 | Names for new sync-file parts clash with existing `TaskHistory`/`Labels` | `SyncFile.cs` | New optional parts `tasks`, `labels`, `views` (+ `taskLog`, see 16); ADR 72 `taskHistory` keeps its name and shape | `02` §5 lists `taskHistory` but ADR 72 already owns that name with another shape |
| 10 | Bin `next` (Shelf › Next) has no old-field home | `SyncLaterItem` | Write `next` into old `later` plus an optional `bin` marker on the item; reverse read ignores an old item as a bin change when the marker or stamps say it did not move | Old builds still show the task (as Later); no loss |
| 11 | Cap is "3 actions, setting 2-5" but code counts tasks and `MaxTasks` is a const | `SessionTasksService.MaxTasks`, `TaskAllowance`, `PickTasksViewModel` | Count actions (stepless task = 1, focused step = 1); the setting lives in the new `tasks.settings` document and defaults to 3; remote `taskAdd` over the cap goes to Queued like "Add anyway" refusals do today | Keeps ADR 25/over-limit rules; never loosens a running session |
| 12 | Title bar is 34 DIP, spec says 40 | `MainWindow.axaml` | 40 per spec | Prototype wins |
| 13 | Label colour with opacity (rgba) vs old `#RRGGBB` fields | `SyncCategory.Color`, `TaskCategoryColors` | Old fields get the opaque `#RRGGBB`; new `labels` carries rgba | Old builds validate `#RRGGBB` |
| 14 | "Ring even when muted" needs Core Audio; none in the repo | `Platform.Windows` | Port in Core + Windows implementation behind the setting, safe restore on exit/crash | CLAUDE.md: OS code only in `Platform.Windows`; no new dependency (use P/Invoke COM) |
| 15 | Plan asks for migration/merge unit tests; repo CLAUDE.md and the owner's rules say no tests unless asked | `01` Phase 1 vs `CLAUDE.md` | No tests added; migration is verified by count checks against the pre-migration backup and a dry-run log (no titles) | Owner rule wins; revisit if the owner asks for tests |
| 16 | History needs snapshots on every device (Bring back, Do again; a task moved to History is a tombstone in `tasks`) but Q9 said History is derived | `Core/Sync/SyncFile.cs` | Added a 4th optional part `taskLog` (`SyncTaskLogItem`, entry id = task id, 30 d); ADR 72 `taskHistory` untouched. Supersedes the "derived" half of Q9 | A derived History loses the snapshot of a deleted/aged-out task on other devices |
| 17 | `baseHash` (single) gives false conflicts for two edits in a row on one device | `TaskFieldStamp.Bases`, `TaskFieldMerge` | Title/note stamps keep up to 10 earlier value hashes (`bases`); "descends" = other value's hash in my bases; the newer stamp decides when both or neither descend | Order-independent; verified by 300 random pairs |
| 18 | HANDOFF table: a `later` item without the marker whose EditedAt > bin stamp moves Next → Later | `OldTaskFieldsReader.BinChange` | Never: an old item in `later` never moves a task between Next and Later (the old app can't express it); only a list change, tick or untick moves bins | Otherwise every phone edit of a Next task would turn it into Later |
| 19 | "Old item newer than the PC task's stamps": all stamps or that field's? | `OldTaskFieldsReader.Apply` | Per field: old EditedAt > that field's stamp | "All stamps" loses a phone edit whenever the PC edited any other field later; per field is never worse than today's item-level rule |
| 20 | Come-back vs parked thought: no field tells them apart | `capture.comebacks` / `SyncParked` | Every come-back gets origin "Parked <ddd M/d h:mm AM>" from CreatedAt (`TaskOrigins.ComeBackTo` exists, unused) | Keeps the capture time visible; owner may prefer "Come back to" |
| 21 | Auto-saved origin date: plan day or save time | `TaskMigration.FromAutoSaved` | `WrapUpOf` (the plan day the card wrapped up): "Auto-saved Thu 11/5" | The day the task belonged to |
| 22 | History keeps 30 d (spec) but ticked Later items were kept 90 d; old `later` shows finished ones 90 d | `TaskHistoryEntry.Kept`, `OldTaskFieldsWriter.FinishedShown` | M1 keeps both numbers; **M2 must not prune migrated History entries before the old documents' rollback release ends** (or keep 90 d for one release) | Otherwise ticked Later items 30-90 d old disappear earlier than today |
| 23 | Old filter status "Unfinished" has no bin | `TaskMigration.Views` | Left out of the view (counted in `UnmappedStatuses`); other statuses map to `Bins` (new optional cfg field) | Unfinished-from-PC stays its own list (Q6) |
| 24 | `devices` with 2+ entries can't be expressed in old fields (`LocalTo` is one keeper) | `OldTaskFieldsWriter` | Written as syncing everywhere for old apps | Only reachable once the UI sets multi-device lists (M3+); revisit with Android run |
| 25 | Old lists hold several bins (`nextTasks` = session+queued+done; `later` = next+later) with one position order | `OldTaskFieldsWriter.OldPosition` | Positions offset by 1,000,000 per later bin (queued/later +1e6, done +2e6); the reader subtracts | Old apps keep the bins grouped in order |
| 26 | Comparing device ids for "lowest PC" | `TaskNumbering.NumberingDevice` | Lower-case "D" text, ordinal | Kotlin `UUID.compareTo` is signed; the text compare is the same on both |
| 27 | Migration stamps' device | `TaskMigration` | `Guid.Empty` and the old EditedAt (never "now") | Two PCs migrating the same shared lists produce identical items, so merging adds nothing |
| 28 | Label colour vs ADR 62 `ColorEditedAt` | `TaskLabel` | One `EditedAt` per label (name, colour, rings on); old `categories` get it as `colorEditedAt`; a newer old colour is taken as opaque | Item-level newest wins is enough for labels |
