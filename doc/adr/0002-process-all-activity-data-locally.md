# 2. Process all activity data locally

Date: 2026-10-15

## Status

Accepted

## Context

The app continuously observes what the user has on screen: window titles, process names, browser URLs and, when needed, OCR text of window contents. This is highly sensitive data. The product promise is that none of it is ever sent off the device. Later features pull against that promise: syncing focus sessions across devices, and training a small classifier with help from a frontier model.

## Decision

We will process and store all activity data on the device that collected it. The desktop app makes no outbound internet connections. The browser extension communicates only with the local native messaging host. Future device sync will use direct device-to-device transports the user controls (LAN first, then Bluetooth; NAS and USB later) rather than a cloud service. Future model training will use synthetic examples generated by a frontier model; real samples may be sent only when the user explicitly opts in, picks them, and they are redacted, and this is off by default.

## Consequences

Users can trust the app with screen contents, and there is no server to build, host or secure. In exchange, all detection must run within the CPU and battery budget of the user's device, sync only works when devices can reach each other directly, and the classifier will learn more slowly than one trained on real user data. Adding any cloud feature later requires superseding this record.
