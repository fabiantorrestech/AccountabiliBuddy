# 14. Pair the phone with the PC over the local network

Date: 2026-10-20

## Status

Superseded by [45. Delete the Wi-Fi link](0045-delete-the-wi-fi-link.md)

## Context

The Android companion (ADR 13) should work with the PC instead of beside it: show the PC's running session and today's plan, start a session and end one early with the PC's own friction, and receive the PC's profiles, sleep and day bar settings and calendar events without the user importing backup files. Tablets run the same app and link the same way. The user chose to pair by scanning a QR code the PC shows, with the phone's own camera app opening the link, on the same Wi-Fi, encrypted, with nothing going through the internet, and approved the QRCoder library (MIT) for drawing the code. The project's rule is local only, with every connection named in an ADR (ADR 9, ADR 12), and the phone app declares no internet permission; Android has no separate permission for local-network sockets, so reaching the PC needs the INTERNET permission. Both platforms ship TLS (.NET's SslStream, Android's SSLSocket) and the cryptography for a pinned certificate and random tokens. The larger device-sync design (doc/plans/device-sync.md: several PCs, a home server, Bluetooth) is not started; this link is its first, smaller step, and the user asked that it stay light on the phone's battery.

## Decision

We will let one Windows PC act as the hub that Android devices link to over the local network, off by default and turned on in its Setup tab. The PC creates a self-signed certificate (kept with DPAPI), listens on one TCP port, answers only private-network addresses, and shows a QR code drawn with QRCoder that holds an `accountabilibuddy://pair?...` link with its address, port, certificate fingerprint, name and a one-time pairing code that expires after five minutes and five tries. The phone's camera opens the link in the companion; the values can also be typed. The phone connects over TLS, accepts only the pinned certificate, and trades the code for a random device token, which the PC keeps as a hash per device and the phone keeps encrypted with the Android Keystore. On that connection both sides exchange length-prefixed JSON messages, so the PC can push a session change the moment it happens: the session state and today's plan, the profile document, sleep, day bar settings and events when they change, requests to start a session and to end one early (the PC applies its wait and reason rules exactly as in its own window), and the status of Cold Turkey and Curbox. The phone connects only while its screen is on or the app is open, and finds a PC whose address changed with one UDP broadcast it sends on demand; the PC sends no beacons. The phone app gains the INTERNET permission and connects only to paired PCs, which the pinned certificate and a network security configuration that forbids cleartext enforce. Either side can unpair, which revokes the token; on the PC, unpairing counts as a Revoke and is locked during focus.

## Consequences

The phone becomes a remote and a mirror of the PC without any cloud service, and backup import becomes a fallback. The PC runs a listening port while the feature is on, which is new attack surface: it must refuse anything without a valid token, rate-limit pairing, never answer public addresses, and keep ending a session exactly as hard as on the PC. Windows Firewall asks once; the rule follows the install path, which Velopack keeps the same across updates. A raw message protocol means writing the framing and message model by hand on both sides, which a portable model in Core (ADR 4) and a Kotlin mirror keep small. Addresses can change; the phone keeps the last one and asks the network once when it can't connect, and a new scan is the last resort. The Windows app gains QRCoder as a dependency. The phone's manifest now holds the INTERNET permission, which stores and users read as "can reach the internet" even though the code only talks to the paired PC. Sharing usage history over this link is a separate decision (ADR 15), as is reading browser addresses on the phone (ADR 16).
