# AccountabiliBuddy

Windows desktop focus guardian. Runs at startup, watches the visible window on every monitor, compares it to the active focus profile, and escalates (toast → overlay → minimize/block) when the user drifts. An Android companion (ADR 13, `android/`) is in progress; Linux comes later.

## Hard rules
- **Local only, except read-only calendars (ADR 9, supersedes ADR 2), the user's paired devices (ADR 14, 15, 21) and sealed sync files between the user's own devices (ADR 22).** OCR text, window titles, full URLs and reasons never leave the device; guided-session task names and tick times, and their categories (name, colour), go only to the user's paired devices (ADR 24); the PC's open come-backs (text and when) go only to the user's paired devices in the link state and its sealed sync file, read-only on the phone's Today (ADR 30), never to the watch; notes never leave the PC; the readable part of activity history (times, app, domain and its section, classification, session context) goes only to the user's paired devices over the ADR 14 link. The only outbound connections are read-only downloads of iCal links the user adds and Google sign-in + read-only Calendar API calls for accounts the user connects, and Google Drive calls (scope drive.file, the app's own folder "AccountabiliBuddy sync", sealed sync files only; ADR 26, Devices → Google Drive, off until signed in), all in `CalendarNetwork` (one auditable class), plus update checks and downloads from the public releases-only repo `fabiantorrestech/AccountabiliBuddy-releases` (ADR 12, `VelopackUpdater`), and Google Health sleep once ADR 11 is accepted. The browser extension talks only to the local native messaging host. The Android companion talks only to paired PCs (ADR 14: pinned TLS on the local network, the PC as hub, off until turned on; a paired phone can change the day plan, ADR 19: the PC checks it like its own Day plan tab, refuses it during a focus session it counts, and a clash with a PC change asks on the phone with both edit times and the changes listed); its opt-in accessibility reader reads only browsers' address bars and keeps domains (ADR 16). The Pixel Watch companion (ADR 21, `android/wear`) gets only a snapshot (today's plan parts, focus session times and profile names, drift times, focused/planned minutes for today and the week, the running session with its current task and task count (ADR 24), today's lunch (whether it's a workday, the lunch length, start and end), the daily goal in minutes (ADR 29: also in "focusDay"; the phone shows focus against it, the watch an outer ring on the session page and a buzz when it's reached); never window titles, addresses, reasons or notes; plus, ADR 36, the phone's noise player state (playing, the sound's shown name, volume, locked: the headphone lock is on and no headphones) on a Noise page whose buttons and crown (5% a step) send play/pause, skip and volume back to the phone, the only things the watch can control besides its Lunch page (start, I'm back, +5/−5 through the phone) and its own local timers), and nothing until it's linked on the phone (Settings → Pixel Watch): from the phone over Google's Wearable Data Layer as messages only (Bluetooth when near; otherwise Google's end-to-end encrypted relay, on by default; with the relay off, only while the watch is nearby), or, when the phone can't be reached, from the PC over the ADR 14 link as a paired device of kind "watch" (the state without the profile list and "focusDay", never "settings"; it can't start, end or change anything; paired from the PC's QR code through the phone, "Pair my watch instead"). Each route is a switch on the phone. A watch asking for news makes the phone connect to the PC for a moment, only when an answer can reach the watch. "focusDay" follows ADR 15: with Activity history off only the plan goes; unpairing deletes what the phone received. A direct phone-watch Bluetooth route waits for an on-device test. Device sync (ADR 22): progress (the last 14 days of counted sessions and drift, only the fields ADR 15 allows), the day plan, profiles, sleep and day bar settings (and a phone's next alarm, ADR 23, and its estimated wake time per kind of morning, ADR 40: only the two times, today's flexible lunch (start and end; every device takes the newest edit for the day), and a phone's pickups during the other devices' sessions: unlock counts and the longest stretch down, from Usage access, ADR 26; and a phone's smart bedtime, ADR 34: per kind of night (Workdays, Off-Days) only the learned time in bed before waking and its status numbers (nights, time to fall asleep, average time asleep and sleep, made it this week), never sleep sessions or times of phone use) leave a device only as sealed files (AES-256-GCM, key by HKDF from a 40-character link code kept under DPAPI on the PC and the Android Keystore on the phone, never carried with the files), each device writing one file of its own; they're carried by QR codes the PC shows (with an end-of-work reminder), files the user shares or imports, a cloud folder the user picks (on a PC a plain folder, e.g. inside Google Drive for desktop; file names are opaque ids) or the ADR 14 link (the phone carries the other devices' files home, never back the way they came); every method is a switch per device, off until turned on; on a work computer the app opens no connection for it (it only reads and writes the folder; Drive for desktop uploads); a receiver applies what arrives by its own rules (stricter at once, looser after its delay and never during a session, a day plan clash asks); a device with Activity history off sends no sessions or drift; each device's Cold Turkey expected blocks never sync. The phone reaches the cloud folder through a folder another app keeps in step with Drive (e.g. Autosync), chosen with Android's folder picker; off by default, and the app opens no connection for it (Google sign-in in the app would need its own ADR). Any other connection needs a new ADR.
- Core (`src/AccountabiliBuddy.Core`) has **no UI or OS dependencies**. Anything Windows-specific goes in `src/AccountabiliBuddy.Platform.Windows` behind a `Core/Ports` interface (ADR 4).
- Profiles/rules are persisted in a versioned JSON schema so a Kotlin Android companion can read them (ADR 7). Current: v11 (v2: unlock options, off days, lock settings; v3: looser-change delay, ask about unlisted sites; v4: time off and one-off blocks; v5: the day plan (categories Watch/Rest/Sleep, Workdays and Off-Days (shown as "Off-Days" since 2026-10-24; JSON `otherDay`) templates, workdays, one-off days) replaces the weekly schedule, whose blocks, time off and one-off blocks are dropped, ADR 18; v6: the Comms category behaviour (`CommsMigration`: existing plans get the category only; a fresh install's starting plan has two comms windows, 11:30-11:45 and 16:00-16:15); v7: the Pre-Work category behaviour (ADR 31, `PreWorkMigration`: every plan gets the category, no parts); v8: flexible breaks (a part's optional `flexMinutes` and `hintAt`: its times are a window over the work around it, e.g. lunch); v9: a Sleep part's optional `wakeByAlarm` (ADR 33: wake = the wake-up alarm, else the phone's estimate for that kind of morning (ADR 40), else bedtime + the sleep goal; only the bedtime is set, the stored end follows bedtime + goal); v10: a day template's optional `blocks` (ADR 37: `BlockRules`: the blocks it keeps on (null = every block seen on), the re-enable time (midnight by default), the heads-up minutes (5) and lift windows (start, end, Allow or Auto, `BlockRef`s per device); nothing to migrate); v11: block rules' optional `deviceTimes` (when each device's blocks come back on, else `reenableAt`) and `blockTimes` (blocks with their own time, left out of their device's); nothing to migrate); any shape change bumps it with a migration in `ProfileDocumentSerializer`.
- History icons: app icons are read from the program file of a running app; site icons come only from the browser extension (the browser's own favicon cache, Chromium `favicon` permission / Firefox data: URLs). Both are cached as files in the data folder's `icons\`. Never download an icon.
- Detection cascade, cheapest first: process/title/URL rules → OCR only when still unknown. Event-driven, plus a slow periodic recheck. Keep CPU and battery use low.
- Activity history (ADR 8): only times, app (process name), site (domain), the site's section (ADR 17, Reddit, YouTube and GitHub only: `r/<subreddit>`, the channel the extension reports, `owner/repo`; `SiteSections`; adding a site needs the user's OK), classification and session context are stored readable. Window titles, full URLs, OCR text, early-end reasons, notes on sessions added by hand and guided-session checklists are always DPAPI-encrypted (`IDataProtector`); titles, addresses and screen text aren't stored at all when "Keep window titles, full addresses and screen text" is off (Settings → App & data; off on the Work computer type). Kept 90 days; logging and screen reading are revocable in the Setup tab, and screen reading is off by default.

- No escape hatches during focus: Profiles, the Day plan tab, one-off days in Exceptions, Settings and every Setup Revoke/Delete are locked during a focus session the user started. Step away (tray, a global shortcut (Ctrl+Alt+B by default), the on-screen window's Ctrl+Alt button) pauses the countdown: no phase ends while away and on return the phase's start and end move by the time away; a key press, click or scroll after it, or the mouse moved 300 px (straight line) from where it was when stepping away (a twitch or bumped desk isn't back; 2 s grace for the press; after a restart only input since launch) brings the user back; it never shortens a wait or unlocks anything; while away enforcement holds as it was (nothing new is judged, nothing blocked is lifted, the escalation neither moves nor starts over: the engine's phase key ignores the moved start); away stretches are session events (AwayStarted/AwayEnded with the kind Break or Interrupted, DB schema 6) left out of focus totals per session, History shows "stepped away" and "interrupted" apart; stepping away by itself after idle minutes is off by default. The only ways out are ending early (wait + reason), a profile's unlock option (wait + reason, then blocks lift until relock, midnight by default), or, with every task of a checklist made before the session ticked (none parked or removed while open during it) and the session at least 10 minutes old, "End session" at once with the reason "All tasks done" (ADR 25). Only sessions that count down to a set end have that friction: old scheduled blocks (from before ADR 18) and sessions with no set end (count-up Quick Start, "No set end") end on command, with no wait or reason (`BypassPolicy.EndsOnCommand`), also from the phone and when quitting. A killed or crashed app resumes its session at the next launch. Earned time (design K): once the other devices' recorded sessions today (never this PC's own nor sessions added by hand; an open one ends when its file was written; `DeepWorkService.UnlockProgress`) meet the daily goal, the work-hours guard lifts for the rest of the day (one notice "Goal met · … · this computer is open"; it only relaxes: stopping for today is then free, but turning the switch off or removing an app still waits while work is left; lowering the goal waits while work is left, raising it doesn't; raising it above today's total guards again); Today shows the goal across all devices, added sessions included (`DeepWorkService.Progress`, `GoalCardViewModel`), the on-screen window's Ctrl+Alt details a goal line, and "Goal met" comes once a day. Pre-Work parts (ADR 31, amends ADR 18; every computer; `PreWorkService`): the first activity in one with no session running asks "Is today a work day?"; yes: until the part ends or a session starts (which ends Pre-Work for the day), the work-hours apps and the default profile's distracting apps and sites are minimized; no: a 10-minute wait spent planning the day (lines kept as come-backs), then today is a day off on that computer (no Pre-Work, no work-hours guard, no start nudge); an emergency unlock (a reason of 40+ characters and a retyped 12-character code, no pasting; 2 in 7 days) lifts Pre-Work until the part ends and reminds the user to schedule off days in the Calendar tab; the phone shows a quiet "Pre-work until …" notice with pickups. A Pre-Work part may overlap Sleep (the only overlap allowed, `DayTemplateEditing.MayOverlap`), so an early start before the wake time is guarded. Changing the Windows clock doesn't move sessions, waits or countdowns: all time comes from `TrustedClock` (ignores jumps over 2 min, also across restarts in the same boot; after a reboot the Windows clock is trusted). While Windows' Alt+Tab or Task view switcher is in front (at most 10 seconds) nothing is judged, and a new top window is judged only after it stayed on top for 400 ms. Windows of a watched browser that the extension can't see (private windows, profiles without the extension) count as distracting. A watched browser whose extension isn't allowed in private windows (live report, else read from the browser's own settings files) triggers a repeating reminder (closing it snoozes 5 min; no opt-out) and, during focus, all its main windows count as distracting (app-level, minimized) except its own extensions/settings pages.
- Install and data safety (ADR 10): packaged with Velopack into `%LocalAppData%\AccountabiliBuddyApp` (never the data folder's name); updates come from locally built packages or, in the installed app, the public releases repo (ADR 12: Settings → Updates; asks before installing unless automatic updates are on; never installs during a session; dev builds never check). Data stays in `%LocalAppData%\AccountabiliBuddy` across updates and uninstall. A build not run from the install (dotnet run, test copies) uses `%LocalAppData%\AccountabiliBuddy-Dev` instead (title shows "(dev data)"), unless `ACCOUNTABILIBUDDY_DATA_DIR` is set, so dev sessions never mix with real ones. Before a DB migration and on the first run of a new version the DB is copied to `backups\`; a DB newer than the app is refused. At launch, the installed app repoints registrations from another copy (Run key, Start menu shortcut, native-host manifests) to itself; dev builds and test copies never do. Backups (`*.abbackup`): without secrets = plain JSON; with secrets = password AES-GCM; restore overwrite saves a this-PC-only copy first; restore and the setup assistant's import are locked during focus.
- Focus time counts only sessions the user starts (Session tab, quick session incl. count-up, Pomodoro) and past focus sessions the user adds by hand in History (ADR 20: date, times, optional note; stored as session events with mode Added, DB schema 5; no overlap with any recorded, added or omitted session, touching is fine; editable and deletable; striped lighter on the Focus row; clicking empty Focus time on the day bar opens the form there). AccountabiliBuddy runs no scheduled sessions any more (ADR 18: blockers enforce); scheduled blocks from before stay in History but never count as focus (left out by session time, like omitted sessions). A saved scheduled session isn't resumed at launch. The day plan (`DayPlan`, Core) says when the buddy watches (Watch parts = the day bar's planned work); a part whose end isn't after its start is the night before the day it ends on; an end of 00:00 is midnight of its own day.
- Stricter changes apply at once; the day plan always applies at once (except a change that frees today's work hours on a computer whose work-hours guard is on, ADR 28); looser profile changes (`LooseningDetector`) wait `LockSettings.LooseningDelay` (10 min default) with a countdown and Cancel, never take effect during a session, and have no "apply now". Comms windows (schema v6): Comms parts are planned work like Watch parts (`CategoryBehaviorExtensions.IsWork`); on a day whose plan has Comms parts, mail and chat (`CommsApps`: Outlook, Teams, Slack, Thunderbird and their web hosts) are distracting during a session outside them, whatever the profile allows, and left to the profile inside them (a comms part never lifts a block) (`EnforcementEngine.InCommsWindow`); a day without Comms parts leaves them to the profile. Hyperfocus reminder: one quiet reminder after 90 minutes of unbroken focus (a stretch restarts with a focus phase or a return from Step away; none in breaks; off per profile or with interval 0; Settings → Focus sessions; "hyperfocus"). Unknown activity escalates (nudge → overlay, never further) after the grace period; the classify prompt has no "not now": "On track" lasts for the session and needs a reason, "add exemption" is permanent and needs a reason. Plan first: a session's first 7 minutes (time stepped away not counted) hold only the classify prompt for unknowns (`EnforcementEngine.HoldUnknownsUntil`; their grace starts when planning ended, also when it ends early); rules still enforce and drift in those minutes counts in History; "I'm ready" (Focus mode, the on-screen window with Ctrl+Alt) or ticking the first task ends it early; a resumed session doesn't plan again. Learn mode: on a fresh install (the setup assistant never shown before) the first session the user starts holds the prompt for its whole length ("I'm ready" and ticked tasks don't end it), never opens the stacked prompt, and leaves what it saw to the review card (`LearnModeService`, "learn.firstSession"); a computer set up before never gets it. Then one stacked prompt lists every unknown seen meanwhile as rows (scope per row, Distracting / On track / Exempt, one reason for the allows; rows left unanswered are asked one by one as usual). After each session a review card on Today lists what it used for a minute or more with no rule (Distracting = block at once, Fine = allow into the session's profile and the pre-ticked ones with a reason, Ignore = never proposed again); History has the same for the week ("Review new this week", rules to a profile picked there); a site or app called "On track" in 3 sessions of the last 30 days is offered on the card once as always allowed. For a browser tab it asks first "the whole site" or "only certain parts" (the page's section: subreddit, repo or YouTube channel, else its first path step; only this page, without query or fragment; or only this view by title; `SiteParts`), for allowing and Distracting alike; the rest of the site is still asked about.

## Conventions
- Explicit, readable code; SOLID; one public type per file; file-scoped namespaces; nullable enabled.
- No tests unless asked (Core is designed to be unit-testable).
- Times shown to the user are 12-hour with AM/PM (e.g. 4:05 PM) on the PC, the phone and the watch, whatever the system's 24-hour setting; never 24-hour.
- A new or reworked feature that needs setting up gets an entry in SetupFeatures (PC `src/AccountabiliBuddy.App/Services/Setup/SetupFeatures.cs`, phone `android/app/.../setup/SetupFeatures.kt`) with the version it arrives in, its "set up?" check and its assistant page, so existing installs can set it up from the migration assistant (5 taps on the About logo, on the PC and the phone; a quiet "New since your last version" card on Today after an upgrade, "Not now" until the next version).
- Icons come from the Material icon libraries (ADR 32): `Material.Icons.Avalonia` on the PC, `material-icons-extended` on the phone; the same meaning gets the same icon on both (the phone's titles map in `SectionIcons`).
