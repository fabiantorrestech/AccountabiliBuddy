# AccountabiliBuddy

Windows desktop focus guardian. Runs at startup, watches the visible window on every monitor, compares it to the active focus profile, and escalates (toast → overlay → minimize/block) when the user drifts. An Android companion (ADR 13, `android/`) is in progress; Linux comes later.

## Hard rules
- **Local only, except read-only calendars (ADR 9, supersedes ADR 2) and the user's paired devices (ADR 14, 15).** OCR text, window titles, full URLs and reasons never leave the device; the readable part of activity history (times, app, domain and its section, classification, session context) goes only to the user's paired devices over the ADR 14 link. The only outbound connections are read-only downloads of iCal links the user adds and Google sign-in + read-only Calendar API calls for accounts the user connects, all in `CalendarNetwork` (one auditable class), plus update checks and downloads from the public releases-only repo `fabiantorrestech/AccountabiliBuddy-releases` (ADR 12, `VelopackUpdater`), and Google Health sleep once ADR 11 is accepted. The browser extension talks only to the local native messaging host. The Android companion talks only to paired PCs (ADR 14: pinned TLS on the local network, the PC as hub, off until turned on); its opt-in accessibility reader reads only browsers' address bars and keeps domains (ADR 16). Any other connection needs a new ADR.
- Core (`src/AccountabiliBuddy.Core`) has **no UI or OS dependencies**. Anything Windows-specific goes in `src/AccountabiliBuddy.Platform.Windows` behind a `Core/Ports` interface (ADR 4).
- Profiles/rules are persisted in a versioned JSON schema so a Kotlin Android companion can read them (ADR 7). Current: v5 (v2: unlock options, off days, lock settings; v3: looser-change delay, ask about unlisted sites; v4: time off and one-off blocks; v5: the day plan (categories Watch/Rest/Sleep, Workdays and Other days templates, workdays, one-off days) replaces the weekly schedule, whose blocks, time off and one-off blocks are dropped, ADR 18); any shape change bumps it with a migration in `ProfileDocumentSerializer`.
- History icons: app icons are read from the program file of a running app; site icons come only from the browser extension (the browser's own favicon cache, Chromium `favicon` permission / Firefox data: URLs). Both are cached as files in the data folder's `icons\`. Never download an icon.
- Detection cascade, cheapest first: process/title/URL rules → OCR only when still unknown. Event-driven, plus a slow periodic recheck. Keep CPU and battery use low.
- Activity history (ADR 8): only times, app (process name), site (domain), the site's section (ADR 17, Reddit, YouTube and GitHub only: `r/<subreddit>`, the channel the extension reports, `owner/repo`; `SiteSections`; adding a site needs the user's OK), classification and session context are stored readable. Window titles, full URLs, OCR text and early-end reasons are always DPAPI-encrypted (`IDataProtector`). Kept 90 days; logging and screen reading are revocable in the Setup tab, and screen reading is off by default.
- App-owned preferences and device-local state (quick session, privacy, integrations, watched browsers, the running-session checkpoint, the current unlock, pending looser changes, calendar sources/events/cache/settings, the clock anchor, setup-assistant state, the last-run app version, the day bar and on-screen timer/timeline settings ("daybar": range, day start/end, the timeline's rows Calendar/Plan/Focus/Blockers in order and shown or not, calendars left off the timeline, Cold Turkey's blocks on or off; default timer; per-profile use default/on/off + colour), the time-up sounds, the noise player ("noise": folder, own volume, repeat, last file, shown names for files, media keys on/off, global shortcuts for play/pause and volume ±10%), sleep mode ("sleep": on/off is the user's; bedtime/wake follow the day plan's Sleep parts, Workdays = weeknights) and the last night the bedtime reminder came ("sleep.lastReminder"), whether the plan took the old sleep times ("dayplan.sleepSeeded"), omitted sessions (by start time; left out of day bar and totals; key "history.notReal"), History display names for apps/sites ("history.names") and apps/sites hidden from Most used / Top distractions ("history.hidden", "history.hiddenDistractions"), app/site time deleted from History per period ("history.deleted": kept on disk, left out of every total, restorable; can be one section of a site), whether past history got its sections ("history.sectionsFilled"), each app's program file for History's "Show in File Explorer" ("history.appPaths", remembered when the app is seen running), linked devices (ADR 14: "devices.settings" on/off + port, "devices.paired" with token hashes only, "devices.identity" the TLS certificate DPAPI-encrypted), the Cold Turkey blocks each profile expects ("coldturkey.expected"; Cold Turkey's own settings are only read, from a copy, never changed), update settings ("updates"), Google setup guide progress; iCal addresses and Google tokens DPAPI-encrypted) live in the `documents` table via `SqliteJsonDocumentStore`, never in the shared profile JSON.
- No escape hatches during focus: Profiles, the Day plan tab, one-off days in Exceptions, Settings and every Setup Revoke/Delete are locked during a focus session the user started. The only ways out are ending early (wait + reason) or a profile's unlock option (wait + reason, then blocks lift until relock, midnight by default). Only sessions that count down to a set end have that friction: old scheduled blocks (from before ADR 18) and sessions with no set end (count-up Quick Start, "No set end") end on command, with no wait or reason (`BypassPolicy.EndsOnCommand`), also from the phone and when quitting. A killed or crashed app resumes its session at the next launch. Changing the Windows clock doesn't move sessions, waits or countdowns: all time comes from `TrustedClock` (ignores jumps over 2 min, also across restarts in the same boot; after a reboot the Windows clock is trusted). Windows of a watched browser that the extension can't see (private windows, profiles without the extension) count as distracting. A watched browser whose extension isn't allowed in private windows (live report, else read from the browser's own settings files) triggers a repeating reminder (closing it snoozes 5 min; no opt-out) and, during focus, all its main windows count as distracting (app-level, minimized) except its own extensions/settings pages.
- Install and data safety (ADR 10): packaged with Velopack into `%LocalAppData%\AccountabiliBuddyApp` (never the data folder's name); updates come from locally built packages or, in the installed app, the public releases repo (ADR 12: Settings → Updates; asks before installing unless automatic updates are on; never installs during a session; dev builds never check). Data stays in `%LocalAppData%\AccountabiliBuddy` across updates and uninstall. A build not run from the install (dotnet run, test copies) uses `%LocalAppData%\AccountabiliBuddy-Dev` instead (title shows "(dev data)"), unless `ACCOUNTABILIBUDDY_DATA_DIR` is set, so dev sessions never mix with real ones. Before a DB migration and on the first run of a new version the DB is copied to `backups\`; a DB newer than the app is refused. At launch, the installed app repoints registrations from another copy (Run key, Start menu shortcut, native-host manifests) to itself; dev builds and test copies never do. Backups (`*.abbackup`): without secrets = plain JSON; with secrets = password AES-GCM; restore overwrite saves a this-PC-only copy first; restore and the setup assistant's import are locked during focus.
- Focus time counts only sessions the user starts (Session tab, quick session incl. count-up, Pomodoro). AccountabiliBuddy runs no scheduled sessions any more (ADR 18: blockers enforce); scheduled blocks from before stay in History but never count as focus (left out by session time, like omitted sessions). A saved scheduled session isn't resumed at launch. The day plan (`DayPlan`, Core) says when the buddy watches (Watch parts = the day bar's planned work); a part whose end isn't after its start is the night before the day it ends on; an end of 00:00 is midnight of its own day.
- Stricter changes apply at once; the day plan always applies at once; looser profile changes (`LooseningDetector`) wait `LockSettings.LooseningDelay` (10 min default) with a countdown and Cancel, never take effect during a session, and have no "apply now". Unknown activity escalates (nudge → overlay, never further) after the grace period; the classify prompt has no "not now": "On track" lasts for the session and needs a reason, "add exemption" is permanent and needs a reason.

## Stack
- .NET 10 (LTS), C#, Avalonia UI (ADR 3)
- Windows platform project targets `net10.0-windows10.0.19041.0` (WinRT: Windows.Media.Ocr, Windows.Graphics.Capture)
- Win32 interop via CsWin32; SQLite via Microsoft.Data.Sqlite (ADR 6); DI via Microsoft.Extensions.Hosting; MVVM via CommunityToolkit.Mvvm
- Browser: one MV3 extension for Chromium (Chrome, Brave, Edge, Opera) + Firefox manifest; native messaging host ↔ App via named pipe (ADR 5)

## Layout
```
src/AccountabiliBuddy.Core/              domain, engines, ports, storage
src/AccountabiliBuddy.Platform.Windows/  Win32/WinRT adapters
src/AccountabiliBuddy.App/               Avalonia tray app
src/AccountabiliBuddy.NativeHost/        browser native messaging host
extensions/                              browser extension (shared + per-browser manifests)
android/                                 Android companion (Kotlin, Compose; doc/plans/android-companion.md)
doc/adr/                                 architecture decision records
handoffContext/                          agent handoff (gitignored)
```

## Commands
```
dotnet build AccountabiliBuddy.sln
dotnet run --project src/AccountabiliBuddy.App   # uses %LocalAppData%\AccountabiliBuddy-Dev (not your real data)
pwsh scripts/package.ps1 [-Version x.y.z] [-Publish]   # installer + portable zip in releases/; -Publish uploads them to the public releases repo (needs vpk 1.2.161 and gh auth login)
cd android && JAVA_HOME="C:/Program Files/Android/Android Studio/jbr" ./gradlew assembleDebug   # Android companion APK (app/build/outputs/apk/debug)
cd android && JAVA_HOME="C:/Program Files/Android/Android Studio/jbr" ./gradlew assembleRelease   # small R8 build (~2.5 MB), signed with this PC's debug key so it installs over the debug build
```

## Roadmap
MVP milestones M0–M7 (setup → core → watcher → app shell → enforcement → browser → OCR → logging) are done, plus the quick-session popup and two anti-escape passes (Setup lock, session resume, unseen browser windows, unlocks, off days; delayed looser changes, unknown escalation, ask about unlisted sites, scheduled end-early wait), the Exceptions tab (time off, one-off blocks, in-app events, iCal links, Google Calendar), the setup assistant (imports from Cold Turkey, AppBlock, BlockSite, LeechBlock, pasted lists), backups and the Velopack installer, the day bar (planned vs actual focus, events, live now line) and the on-screen window (click-through, Ctrl+Alt drag): per-profile session timer with a global default (styles, marks) and the all-day timeline (days with focus blocks; swaps with the timer or stacks); hover fades it, Ctrl+Alt Hide button; white glow + chime when focus or a break is up; sleep mode (day bar runs wake to bedtime, night and lost sleep shaded, evening "sleep if you go now" line coloured by hours). Android companion (`android/`, plan in `doc/plans/android-companion.md`): imports the PC's backup (profiles v4, sleep, day bar, events; readable or password), Today/Profiles/Settings, Health Connect sleep, pinned colorized timeline notification (foreground service, BridgeCal pattern), home-screen widget, bedtime reminder, phone use vs. planned focus (Usage access), Curbox status via its API; PC remote designed (ADR 14, Proposed). Cold Turkey status (Session tab card from a copy of its settings; per-profile expected blocks, named at focus start; Cold Turkey is never changed: editing its settings file was tested and it rewrites it from its own copy). Count-up Quick Start (quick session "Count up": a Quick Start profile, made on first use or chosen in Settings, with no set end; the on-screen bar fills each hour, glows every 30 min with the time in). Linked devices (`doc/plans/linked-devices.md`, ADR 14-16 Accepted): L5 done; L1 built (Core `Link/`: framed JSON over pinned TLS, pairing by QR code from Setup → Linked devices, start and end early from the phone with the PC's own wait and reason; Android `link/` + PC card); L2 built (the PC pushes profiles, sleep, day bar and visible-calendar events as a hashed `settings` message; no more backup imports); the phone finds the PC again by one UDP "where" broadcast when its address changed (`LinkDiscoveryResponder`, same port). Verified on the user's PC and Pixel 7. The PC listens only while Windows marks its Wi-Fi/Ethernet network Private (`INetworkTrust`, `WindowsNetworkTrust`; paused with a Setup note on Public). Profiles tabs on both apps group by device once linked (this device first; profile count, running or "blocks on" profile, last seen/synced; the phone uses the PC's profiles). Noise player (sidebar bottom left and the on-screen window's Ctrl+Alt details: ⏮ ⏯ ⏭, repeat on by default, own volume, a pencil to rename how a file is shown (the file keeps its name); the sidebar keeps its width and long names are cut with "…"; a folder of sounds chosen in Settings, Music\Noise by default; Windows' MediaPlayer via `INoisePlayer`/`WindowsNoisePlayer`, created on first Play; media keys off by default; global shortcuts incl. arrows/Page Up/Down). History breaks Reddit, YouTube and GitHub down by subreddit, channel and repo under their site, in Most used and Top distractions (ADR 17, DB schema 4; past Reddit/GitHub entries filled in once from their encrypted addresses). Next: the body-double redesign (`doc/plans/2026-10-20-body-double-design.md`, approved; AB notices drift and hands sites to the blockers, which enforce). B1 built (`doc/plans/2026-10-20-day-plan-b1-plan.md`): schema v5 day plan, the Day plan tab (drag bar + list, categories, workdays), one-off days in Exceptions, sleep from the plan, no scheduled sessions, phone reads v5. B2 built (`doc/plans/2026-10-20-timeline-b2-plan.md`): the day bar and the on-screen timeline are rows (Calendar in calendar colours, Plan in category colours, Focus with red drift marks from History, Blockers = Cold Turkey's blocks striped amber; order, rows, calendars and Cold Turkey set in Settings → Day bar); the phone's Today header, notification and widget draw the plan's parts in their colours. Then: Settings reorganisation + app-wide search (asked 2026-10-20), flexible lunch, B3 phone screens (four rows on the phone), the buddy, session checklist/reflection, progress. Cold Turkey's command line `-add "<block>" -web <site>` reaches a running Cold Turkey at once (tested on a throwaway block). L3-L4 after that. Backlog: progress heatmap; Shorts/Reels and part-of-site blocking on the desktop (from Curbox). Device sync is planned in `doc/plans/device-sync.md` (not started). Post-MVP: V2 habit suggestions + distilled local classifier (synthetic frontier-generated data; real samples opt-in and redacted only); V3 Android companion + LAN/Bluetooth sync, Linux, tamper resistance.

## Conventions
- Explicit, readable code; SOLID; one public type per file; file-scoped namespaces; nullable enabled.
- No tests unless asked (Core is designed to be unit-testable).
